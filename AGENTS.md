# AGENTS.md

Guidance for AI coding agents working in this repository. People use
the same commands. The rules for AI-assisted contributions are in
[CONTRIBUTING.md](CONTRIBUTING.md), under "Using AI Tools".

## Layout

- `pysrc/bytewax/`: the Python API, most operators and connectors.
- `src/`: the Rust core: the Timely dataflow runtime, the core
  operators, the PyO3 bindings and the recovery store. Its unit tests
  live next to the code.
- `pytests/`: the Python tests.
- `docs/`: Sphinx docs in MyST Markdown. Code in `{testcode}` blocks
  runs as doctests.
- `requirements/`: lock files generated by `uv pip compile` (the
  `venv-compile-all` recipe). Don't edit them by hand.

## Setup

You need uv, Python 3.12, `just`, `cbfmt` (for the pre-commit hooks)
and the Rust toolchain pinned in `rust-toolchain.toml`.

```console
$ just get-started
$ . venvs/dev/bin/activate
(dev) $ just develop
```

`just get-started` creates `venvs/dev/` and installs the pre-commit
hooks. Most recipes need the `dev` venv active. `just develop`
rebuilds the Rust extension into it; run it again after every change
to Rust code.

## Checks

Run these before you push:

```console
(dev) $ just lint
(dev) $ just test-py
(dev) $ just test-rs
(dev) $ just test-doc
(dev) $ just lint-pc
```

`just lint` runs vermin, ruff, mypy and `cargo clippy`; `just lint-pc`
runs every pre-commit hook on all files.

The Kafka tests are skipped unless `TEST_KAFKA_BROKER` is set. Start a
local broker with `./scripts/ci-kafka.sh start` (it needs Java 17 or
newer and port 9092), run the tests with
`TEST_KAFKA_BROKER=localhost:9092`, and stop the broker with
`./scripts/ci-kafka.sh stop`.

## Conventions

- A bug fix comes with a test that fails without the fix and passes
  with it.
- User-visible changes get an entry under "Latest" in `CHANGELOG.md`.
- Keep public APIs and defaults compatible; add new behaviour as an
  opt-in.
- One concern per PR. Open it as a draft until CI is green.
- Write code, comments, commit messages and PR descriptions in
  English.
- Don't add a `Signed-off-by` trailer for the person who submits the
  change; they add the DCO sign-off themselves.

## Reporting results

Follow "Using AI Tools" in CONTRIBUTING.md: report only what you ran,
run every check at least five times and say how many runs passed,
name the build (debug or release) and the machine for timings, and
say plainly what you did not verify.
